# Conversion test result (2026-10-05)

`npm i && node --test test/convert.test.mjs` bundles `src/exporter.ts` for Node, converts 33 fixtures plus a 5,000-line document, a pathological-input check and the shipped `docs/app.js` through a stubbed page, then unzips each .docx and checks that `document.xml` is complete and that the expected text (and structure such as headings, lists, tables, hyperlinks) is present and that raw markup is not. Before the fixes 28 of 36 tests passed; after, 36 of 36 pass. The failures were real-world syntax the parser ignored: setext headings (`Title` / `=====`), indented code blocks, reference-style links (`[a][1]` plus `[1]: url`), `<https://...>` autolinks, HTML comments, inline/block HTML tags (`<div>`, `<img>`, `<kbd>` leaked into the Word file as literal text), linked badge images (`[![alt](img)](url)`) and a trailing backslash line break. All fixed in `src/parser.ts`; `docs/app.js` was rebuilt. The 5,000-line document converts in about 0.5 s. Known gaps, not fixed: ordered lists always restart at 1 (a list starting at `3.` shows `1.`), remote images become a placeholder by design, footnotes are Pro-only (free output keeps the `[^1]` marker and the definition line), and `<a href>` tags lose their link (text kept).
